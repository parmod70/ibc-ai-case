Spec-driven delivery: how I would manage the build

A small pilot still needs clear decisions, evidence and a repeatable way of working.

DMAIC identifies and validates the operational improvement; spec-driven delivery turns the agreed findings into small, testable product increments.

STAGE 01 assignment

Proposition brief

Define the user problem, intended value, controls and success measures.

STAGE 02 account_tree

Prioritised use cases

Map the highest-value user journeys, decisions, exceptions and owners.

STAGE 03

Agreed specification

Write expected behaviour in Markdown: requirements, acceptance criteria, data rules and integration/tool contracts.

STAGE 04 deployed_code

Build a bounded increment

Build one small change against the real portal and integration architecture.

STAGE 05 rule

Prove it works

Run deterministic checks, workflow tests and human review on the actual user path.

STAGE 06 published_with_changes

Release and learn

Demonstrate against agreed criteria, capture evidence, release safely and improve the next specification.

Artefact trail

Proposition brief→use-case backlog→agreed specification→working increment→test evidence→release decision and reusable learning
Operating Principle

“Use AI to accelerate delivery, while keeping requirements, test evidence and release decisions under human control.”

Applied iteratively: begin with the smallest useful workflow, prove it with users and data, then extend only where the evidence supports it.
